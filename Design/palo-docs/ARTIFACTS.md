# Artifacts

Non-code material produced or used during Lumen's development: diagrams, prompts used with AI tools, screenshots, test data.

## AI tools used during development

Per the brief: "AI tooling is encouraged if you can explain and defend every choice." This section is the explainable trail.

### Models and their roles

| Tool | Model | Used for |
|---|---|---|
| Claude (Anthropic) | Opus 4.7 (1M context) | Architecture review, ADR drafting, this documentation, competitive analysis synthesis |
| Claude (Anthropic) | Sonnet 4.6 | Routine code generation (SwiftUI views, repository implementations), test generation |
| OpenAI | GPT-4o-mini | Inline code completion in Xcode 26 (Predictive Code Completion) |

### How prompts are stored

Reusable system prompts (for the in-app waterfall AI) live in `lumen/Data/AI/Prompts/`. Each prompt is versioned and accompanied by a brief rationale.

For development-time prompts (used to generate code with Claude / GPT), the policy was:
- One-shot prompts: discarded after the generated code was committed and reviewed.
- Reusable patterns (e.g. "generate a SwiftData repository for a Domain entity"): saved in `docs/dev-prompts/` for future reuse.

## Honest acknowledgements

- The competitive analysis (Fabulous, Alarmy, Opal, Rise) was synthesised by Claude based on web research with cited sources. I reviewed and edited the conclusions; the positioning angle ("the only morning ritual that starts at the alarm") is mine but emerged from the research.
- ADR drafts were initially generated by Claude based on bullet-point inputs I provided, then iterated and refined manually until I could defend each line.
- The SwiftUI scaffolding and repetitive Domain entity boilerplate were largely generated; the Domain logic, the AI waterfall orchestration, and the alarm state machine were hand-written and reviewed line by line.

This trail exists so that, in the technical defence, every architectural and behavioural choice can be traced back to its rationale — whether AI-assisted or not.
